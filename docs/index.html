What this adds

  • 01

    Dual compression: clustered local training plus server self-compression after aggregation.

  • 03

Abstract

Federated Learning (FL) is a promising technique for the collaborative training of deep neural networks across multiple devices while preserving data privacy. Despite its potential benefits, FL is hindered by excessive communication costs due to repeated server-client communication during training. To address this challenge, model compression techniques, such as sparsification and weight clustering are applied, which often require modifying the underlying model aggregation schemes or involve cumbersome hyperparameter tuning, with the latter not only adjusts the model's compression rate but also limits model's potential for continuous improvement over growing data. In this paper, we propose FedCompress, a novel approach that combines dynamic weight clustering and server-side knowledge distillation to reduce communication costs while learning highly generalizable models. Through a comprehensive evaluation on diverse public datasets, we demonstrate the efficacy of our approach compared to baselines in terms of communication costs and inference speed.

How it works

FedCompress

01

Learn task and compression together

Each client minimizes cross-entropy plus a weight-clustering penalty. The local warm-up uses β=0 before enabling clustering with β=1.

Lk=Lce+βLwc(θk,μ,C)

Equation 1, PDF page 3. μ denotes learnable centroids; C is their count.

02

Restore clusters after aggregation

Keep the underlying aggregation rule. Then optimize a clustered student to match the temperature-scaled teacher outputs on unlabeled auxiliary data held by the server.

Ls=LKL(pT∥p)+βLwc

Equation 2, PDF page 4, with model arguments abbreviated. The KL term includes the paper’s temperature scaling.

03

Measure representation diversity

Normalize the singular values of local embeddings and compute their effective rank. This is an unlabeled proxy for representation quality, not a generalization guarantee.

E=exp(−∑jrjlogrj)

Dynamic weight-clustering section, PDF page 4. r is the normalized singular-value spectrum; the implementation description adds a small stability constant.

04

Use the score to adjust capacity

Start with a small cluster count and increase it when score progress stalls. The prose uses a three-round window and patience, with an optional maximum cluster budget.

PDF page 4. This describes the intended schedule; Appendix A contains notation differences and is not an independently verified implementation.

Takeaways

  • Server recompression matters: client clustering alone leaves little bidirectional saving in the CIFAR-100 ablation.
  • The savings require 10 extra server epochs per round and auxiliary unlabeled data.
